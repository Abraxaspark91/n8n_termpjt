## 요건

승인된 변경사항을 투자 대시보드와 관련 산출물에 반영한다.

- 투자 대시보드를 거시경제 현황 패널과 개별 종목 펀더멘털 분석 패널로 독립 구성한다.
- 거시경제 패널에 금리, 물가, 환율, 주요 지수 등 시장 전반 지표를 배치한다.
- 개별 종목 패널에 PER, PBR, 부채비율, 잉여현금흐름을 기본 지표로 제공한다.
- 재무·밸류에이션·실적·컨센서스 지표로 확장 가능한 구조를 반영한다.
- 지표 갱신 주기를 실시간, 일중, 일간, 주간, 월간, 발표 시점으로 분류한다.
- 지표별 목표 갱신 주기를 정책서에서 지정할 수 있도록 한다.
- 각 지표에 기준 시각, 최종 갱신 시각, 데이터 출처 및 지연 여부를 표시한다.
- 패널별 로딩 실패, 지연 데이터, 서로 다른 기준일 데이터 혼재 및 사용자 경고 처리를 검증한다.

## 결정

다음 산출물의 변경사항을 승인하고 실행 결과에 반영된 것으로 기록한다.

- 투자 대시보드 기능정의서 / 대시보드 UI·패널 구성 / add
- 지표 갱신 정책서 / 데이터 갱신·기준 시각 관리 / add
- 데이터 요구사항 정의서 / 거시경제·개별 종목 펀더멘털 데이터 / add
- 테스트 시나리오 / 패널 분리·데이터 갱신 검증 / add
- 산출물_설계서.docx / 통합 산출물 설계 / modify
- 요구사항_추적표.xlsx / 요구사항·데이터 신선도 추적 / modify
- 보고_장표.pptx / 프로젝트 보고 / modify

실행 결과 초안에 따르면 산출물_설계서.docx, 요구사항_추적표.xlsx, 보고_장표.pptx는 deliverable_patch를 통해 GitHub Actions 문서엔진에서 갱신 후 GitHub에 커밋되었다고 보고되었다.

DA verdict는 보완 권고(score 5)이다. 따라서 구현·공개 범위 확정 전에 대상 국가·시장·자산군, 세부 산식, 데이터 계약 및 제공업체, 라이선스, 허용 지연 시간(SLA), 공통 데이터 모델, 고객 고지 및 투자정보 컴플라이언스를 별도 승인 게이트에서 확정한다.

## 영향 산출물

- 투자 대시보드 기능정의서: 독립 패널 구성, 기본 지표 및 확장 구조
- 지표 갱신 정책서: 갱신 유형, 목표 주기, 기준 시각, 최종 갱신 시각 및 지연 표시 규칙
- 데이터 요구사항 정의서: 거시경제·개별 종목 펀더멘털 데이터와 신선도 표시 요건
- 테스트 시나리오: 패널별 로딩 실패, 지연 데이터, 기준일 혼재 및 사용자 경고 검증
- 산출물_설계서.docx: 통합 산출물 설계 변경
- 요구사항_추적표.xlsx: 요구사항 및 데이터 신선도 추적 항목 변경
- 보고_장표.pptx: 패널 분리, 갱신 정책, 데이터 신선도 및 후속 확정 항목 반영
- LLM Wiki: 본 요구사항과 결정 로그 및 인덱스 추가

## 리스크

- 지표별 발표 주기와 데이터 지연 차이로 두 패널의 기준 시각이 일관되지 않을 수 있다.
- 실시간 또는 고빈도 갱신 적용 시 데이터 제공 비용과 시스템 부하가 증가할 수 있다.
- 지표 산식과 데이터 출처가 확정되지 않으면 동일 지표의 값이나 갱신 시점이 달라질 수 있다.
- 공시·컨센서스 반영 지연으로 화면 표시값이 최신 투자 판단과 차이 날 수 있다.
- 대상 범위와 라이선스가 확정되기 전에는 데이터 범위와 구현 일정이 변경될 수 있다.
- 고객 고지 및 투자정보 컴플라이언스 검증 전에는 공개·운영 범위가 제한될 수 있다.

## 오픈 질문

- 거시경제 지표의 대상 국가와 시장 범위는 무엇인가?
- 지원할 대상 자산군과 개별 종목 시장 범위는 어디까지인가?
- 각 지표의 구체적인 목표 갱신 주기와 허용 데이터 지연 시간(SLA)은 얼마인가?
- 지표별 데이터 제공업체, 출처 표기 기준 및 라이선스 요건은 무엇인가?
- 지표 산식, 기준일, 타임존, 발표 후 갱신 및 재처리 기준은 무엇인가?
- 공통 데이터 모델과 지표 사전, 데이터 신선도 UX를 어떻게 확정할 것인가?
- 고객 고지 및 투자정보 관련 컴플라이언스 검증 범위는 무엇인가?
